b:Ta70,<h1 id="privacy--data">Privacy &#x26; data</h1>
<h2 id="what-the-board-stores">What the board stores</h2>
<p>On the board's own flash memory only:</p>
<ul>
<li>your Wi-Fi network name and password,</li>
<li>your location (coordinates and place name) and other settings,</li>
<li>your OpenSky credentials, if you add them.</li>
</ul>
<p>None of this is sent to the Flight Board project. The only contact with the
project's website is the optional update check, which sends no ID or
settings. There is no account, analytics or tracking.</p>
<h2 id="who-the-board-talks-to">Who the board talks to</h2>

<td>Live aircraft positions; aircraft details</td>

</tr>
<tr>

<h2 id="what-your-browser-loads">What your browser loads</h2>
<ul>
<li>The dashboard page itself comes from the board.</li>
<li>The page loads the <a href="https://leafletjs.com">Leaflet</a> map library from
unpkg.com, map tiles from <a href="https://www.openstreetmap.org">OpenStreetMap</a>,
and its display font from Google Fonts. These services see your IP address, as with any
web page.</li>
<li>Sound and traffic-history preferences are saved in your browser.</li>
</ul>
<h2 id="your-location">Your location</h2>
<p>Your scan area is sent to OpenSky with every update — that's how it knows
which aircraft to return. Use a nearby town rather than your exact address
if you prefer.</p>
<h2 id="security-notes">Security notes</h2>
<ul>
<li>The dashboard has no password. Anyone on your Wi-Fi can open it and change
settings. Don't put the board on a network you don't trust, and never
expose it directly to the internet.</li>
<li>The board doesn't verify the security certificates of the services it
contacts. That's acceptable for public flight data, but it's one reason
the board should only hold credentials that are low-risk (like an OpenSky
API client) and easy to replace.</li>
